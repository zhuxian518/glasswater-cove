# 撒网打鱼｜产品需求文档 PRD

> 实施进度：首个可玩版本v0.1.0已开发；本文保留v0.4设计基线，已实现和待验收项目见[07号记录](07_首版实现与验证记录.md)。

版本：v0.4 评审稿；2026-10-12。关联：[调研](01_调研与方案分析.md)、[技术设计](03_开发设计文档_TDD.md)、[实施与验收](04_开发计划与验收.md)、[美术与动效规格](05_美术与动效设计规格.md)、[生物与撒网机制](06_生物多样性与撒网机制.md)。

> 本文定义建议开发的产品，不代表已实现。体验方向由用户确认；时长、美术、鱼种、数值为设计建议。所有数值需通过可玩原型调整。

## 1. 产品定位与核心判断

**一句话：开一条小渔船，看准游动的鱼群，把网撒在它们将要经过的地方，享受从等待到收获的过程。**

保留《深海较量》的水面横向移动、向水下投掷和提前量判断，把战斗压力改成有节奏的捕鱼乐趣。首版是 90 秒短局，有清晰开场、变化和收获总结；不用死亡、限次门票或付费强化驱动继续玩。

捕鱼的主要体验链：**发现鱼群 → 选择目标 → 等位置/时机 → 下网 → 观察展开 → 收网确认 → 决定下一网**。得分服务于这条体验链。

### 1.1 已确认的用户要求

- 轻松爽快，一网可以捕到多条鱼，但保留适度技巧。
- 允许没有收获的尝试，同时避免正常操作的玩家长时间没有收获。
- 满网是值得记住的时刻，不能每次出现。
- 有变化和继续探索的理由，不能变成按住按钮的无脑刷取。
- 尽可能借用现有潜艇大战工程，整体界面与美术符合渔船、鱼群、撒网场景。
- 比潜艇题材更休闲，允许提高美术制作投入；画面风格、材质、光影和动效要精致炫酷，不能停在简单几何换皮。
- 海底生物要多样；捕获机制要提供更多可理解的选择与可玩性。

### 1.2 首版设计原则

| 原则 | 具体落地 |
|---|---|
| 判断先于抽奖 | 命中、网口、容量决定捕获，不增加隐藏捕获概率 |
| 普通收获也成立 | 一两条鱼有清晰入网、回船和声音反馈；不显示“差劲”评价 |
| 观察能够改善结果 | 稀疏群、紧密群、交错群和快速单鱼要求不同下网时机 |
| 空网有可读原因 | 鱼已游走、网落在身后或网位被占；不出现视觉命中却随机失败 |
| 满网有机会成本 | 三网位持续占用到回船；盲目撒空网会错过下一群 |
| 变化有预告 | 新鱼的轮廓、游速与方向可观察；稀有鱼进场有克制提示 |
| 过程轻负担 | 不手动拉线、不反复点击收网、不管理鱼饵、耐久和背包 |

## 2. 用户、场景和目标

目标用户是愿意在手机上花 1–3 分钟体验轻量互动的休闲玩家，以及能接受简单预判技巧的街机玩家。这是目标画像，尚未通过访谈验证。

典型场景：从笔记或工具入口点开；第一次很快理解；玩一局获得具体收获；愿意再试一次“刚才那群鱼”或“那条没网到的鱼”。

### 2.1 产品目标

1. 新用户不用长说明就能移动与撒网。
2. 普通玩家获得稳定但有差异的收获；熟练玩家能明显提高命中和一网多鱼能力。
3. 同一场景连续玩三局，仍能看到不同鱼群组合与不同收获。
4. 形成“我的最好一网”“我发现了新鱼”这类具体记忆。
5. 离线完整运行，不依赖后端或运行时远程素材。

### 2.2 首版不承诺的结果

不把“钓鱼受欢迎”直接推导为本产品一定受欢迎，不给出无证据的留存/市场规模预测。真人体验目标与工程正确性分别验收。

## 4. 玩法规则

### 4.1 场景与控制

- 固定侧面水体剖面：上方少量天空、水面一条渔船、下方多层鱼群。
- 船只沿水面左右移动，不能下潜；网从抛出时船的位置进入水下，不随船平移追鱼。
- 手机底部三个按钮：左移、撒网、右移。允许一指移动、一指撒网，也允许先移动后单指撒网。
- 按下撒网抛出一网，按住让网下沉，松手在当前水层张网，之后自动捕获/回收；持续按住不会连发。轻点先到最小展开深度y=320再张开。
- 键盘 A/D 或方向键移动，Space 撒网，P/Esc 暂停。左右同时按为停止。
- 暂停、切后台或失焦清除按压状态；回来先暂停，用户点击继续后恢复。

### 4.2 三网位的含义

最多三张网同时处于抛出、下沉、展开、捕获或收回过程。**回到船上才释放网位**，捕到鱼时不会立即返还。没有整局总网数限制。

最多一张处于受玩家控制的CAST/DESCEND阶段；它进入OPEN后释放控制权，下一次新按下可创建下一张。其他网可以独立展开、捕获或回收，按键不会同时操纵多张网。完整快速点击、到底、暂停接管与输入取消规则见[机制规格第2节](06_生物多样性与撒网机制.md#2-操作边界与保护)。

HUD 显示三个网形槽：可用为实体网图标；占用为进度环。满额时显示“网还在水里，下一群快来了”，提示频率最多两秒一次，不阻挡移动。

### 4.3 一张网的完整生命周期

| 阶段 | 表现与规则 | 初始时长/参数 |
|---|---|---|
| 抛出 | 船员抛网，水面短暂展开，网位立刻占用 | 0.18 秒 |
| 下沉 | 半展开网在固定x向下移动，经过生物不捕鱼；松手请求到达合法深度或到最大深度时展开 | 下沉速度360；最小展开y=320、最大y=1030 |
| 展开 | 网口从小到大，符合范围和容量的生物陆续入网，无触发鱼保底 | 0.25 秒；有效半径12→95 |
| 捕获 | 网口保持，范围内生物仍可入网，小体型占1格、大体型占2格 | 0.45 秒；总空间6格 |
| 收回 | 网兜收拢、鱼在网内可见，回船；停止新增捕获 | 0.65 秒 |
| 到船 | 单网分数和鱼获正式入账，释放网位 | 一次性事件 |

这是为了形成位置与水层选择而采用的**风格化撒网**：真实撒网通常在水面充分展开、下沉收拢；游戏把完整有效网口放到玩家松手时，不作为真实操作教学。具体依据见调研FAO来源。此版替代此前接触鱼自动张网方案。

规则补充：

- 捕获完全由几何与容量决定，不做“命中了但有概率逃掉”。
- 同一条鱼只能归一张网；两网重叠按碰撞时间、网 ID、鱼 ID 稳定仲裁。
- 所有候选按实际入网时间、网ID和生物ID稳定仲裁；容量足够才归属，空间占满6格立即收网，其余继续游动。不足2格的大生物不会挤走已捕目标；剩1格仍可捕小生物。
- 一群是多条独立鱼，不能命中其中一条就让整群消失。允许仅捕到一部分。
- 不在捕获鱼的位置生成新的捕获圈，不发生跨网传染或无限连锁。
- 空网仍经历回收，显示轻量水滴与空网形状；无扣分、嘲讽、强震动。
- 全捕获阶段最长 0.70 秒；动画可以少粒子，规则不随特效档位改变。

### 4.4 结束与最后一网

操作时间 90 秒，不设生命失败。时间到禁止新网、新鱼群和船的控制输入，显示“收最后一网…”。此前已投出的网继续按原规则完成，现有自由鱼继续游动；最多约 3.97 秒后全部回收，进入结算。这样不让最后一网投出后直接作废。

时间到同时对受控下沉网发出张网请求；浅于最小深度的先到y=320再展开，不继续等待已经禁用的松手输入。

正式局不要求达到分数门槛才能结束。0 鱼获也能结算，但正常有参与的玩家大量零收获属于设计失败，需要调参。

## 5. 获得感与可玩性设计

### 5.1 收获分布

希望体验到“这一网一条”“刚好三条”“差点就满了”“终于满网”，而非只有空网与满网两个极端。下表是试玩调参目标，不是运行时用概率抽取结果。

| 表现 | 希望的体验 | 首轮调参目标 |
|---|---|---|
| 空网 | 偶有失手，原因看得懂，能看到下一次机会 | 正常新手正式局空网比例约 20%–40% |
| 普通收获 1–2 条 | 过程的稳定回报，不被贬低 | 构成主要收获之一 |
| 好收获 3–4 条 | 等待、找位置有回报 | 经观察可明显提高频率 |
| 满载6/6格 | 低频高点，可为六个小生物或较少的大生物 | 约占所有完成网次的5%–15%；不作为硬配额；统计个数与占格两种分布 |
| 稀有单鱼 | 发现和追逐感，单条也有记忆 | 每局提供两次可见机会，不保证捕到 |

统计教程与正式局分开；“正常新手”定义为理解教程、正式局至少撒五网并尝试移动的人。故意不操作不能靠系统自动发鱼获。样本小或不同玩家水平下，上述比例可变，不以隐藏随机失败强行凑比例。

### 5.2 观察带来的选择

1. **紧密群**：等群中心来到下网通道，一网较多；太早会只网到前排。
2. **疏散群**：不要追求全收，选择最有价值的局部；空等可能错过下一群。
3. **交错群**：两个不同方向的群将相遇，形成短暂好窗口；需要提前看位置。
4. **快速鱼**：价值较高，提前量更大；追逐它会占用本可捕鱼群的网位。
5. **深层鱼**：下网等待更久、占位更久；不额外叠加深度分，价值由鱼种解释。

首版的技巧集中在**位置、松手水层/时机、目标和容量取舍、网位节奏**。深度通过同一按钮的按住/松手控制，不额外加入蓄力准星、深度菜单或拉线小游戏。详细三类决策例子见[机制规格第6节](06_生物多样性与撒网机制.md#6-三个可审查的玩法例子)。

### 5.3 避免“一直按就最好”

- 深网占位更久；浅层快速松手可得到小获，深层高价值目标值得有意识等待。
- 群间有 1–3 秒的可读空隙，移动到下一条预计通道比原地撒空网更好。
- 紧密群和稀疏群混排；不能把所有鱼摆成必然满网的阵型。
- 捕获范围和容量固定，不靠连续成功不断扩大网口。
- P0 不掉落加速/大网道具，避免“捕得越多→道具越多→越来越无脑”的正反馈。
- 同一种子对比“站桩固定浅网”“移动固定浅网”“观察后选择深度/时机”，再加固定深网诊断；观察策略得分中位数目标比简单移动浅网高至少25%，同时检查是否存在单一水层无脑最优。

若优势主要来自深层高价目标的固定刷点，需调整遭遇、密度和价值；不能把写死的背板当成充分技巧。先让松手选择成立，再独立验证P1网型与提前收拢，不叠加全部机制。

### 5.4 收获反馈的节制

| 结果 | 视觉 | 声音 | 信息 |
|---|---|---|---|
| 一条 | 鱼进入网兜、绳索收拢、回船小水花 | 一声清晰水滴与轻木音 | “+分数 · 1 条” |
| 两到四条 | 网兜逐渐饱满，鱼逐条入网 | 音阶随入网数轻微上行 | 到船后一个合并标签 |
| 占满六格 | 网口亮边、饱满鱼兜、较大的回船水花，符合实际个数与体积 | 短促完整乐句 | “满载 · 鱼获×n” |
| 新鱼 | 本局首次到船出现小型鱼种名签 | 与分数声区分的发现音 | “新发现：金尾鱼” |
| 空网 | 看得见空网回收，不遮挡新鱼群 | 很轻的水声或静默 | 不反复弹失败文案 |

P0 不做命中停顿；鱼群与船不因庆祝冻结。合并飘字、限声部，最多三个得分标签同时显示。音乐默认关、音效默认开，静音状态不影响判断。

## 6. 内容与数值初稿

### 6.1 基础参数

逻辑世界1000×1200、水线y=155，画布等比适配；不是CSS像素。船速440；撒网冷却0.45秒；三个网位、最多一张受控下沉网；六格容量，小生物1格/大生物2格；展开半径95；最小展开y=320、最大y=1030；无独立深度倍率。

以下为风格化游戏配置，不作真实物种分布或捕鱼教学。数值待原型验证。

速度为世界单位/秒初值。虾的尾扇、蟹/龙虾爬行和章鱼舒展属于表现动作，不改变判定大小或临时触发伤害。鱿鱼首版采用可读的恒速横移；喷水突进、躲网、喷墨暂不加入，以免增加不可解释失败。

观赏层另有水母、海马、海星、海胆、珊瑚、海龟，放在远层/边缘，首次标明观赏；不进入捕获、计分，不造成误捕惩罚。活动观赏实例最多6个，静态珊瑚可缓存。完整环境表现见[生物机制规格](06_生物多样性与撒网机制.md#42-环境生物)。

### 6.3 三段节奏与跨局生物组合

每局固定基础F01/F02/F04/F09与稀有F06，再从三个主题组合中选择一个：

| 同一海湾的遭遇组合 | 本局额外三个可捕种 | 体验变化 |
|---|---|---|
| 海草边 | F11鱿鱼、F10海蟹、F12章鱼 | 基础虾群、中层鱿鱼与底层目标取舍 |
| 礁石边 | F03黄鳍鱼、F10海蟹、F13龙虾 | 快速鱼与底层甲壳类的空间/价值选择 |
| 流动水 | F03黄鳍鱼、F11鱿鱼、F12章鱼 | 浅层虾群、快速中层目标与深层章鱼 |

每局可出现8个可捕种；实际看到/捕到数由遭遇与操作决定。三个组合复用一处海湾的主体美术，仅切换少量边缘装饰和出生表，不等于新做三张地图。前三局分别覆盖三个组合，之后由种子轮换；不强迫分享或付费解锁。

三段节奏：

- 0–20秒：F01/F02/F09，权重50/30/20；学习按住与松手，浅层机会清楚。
- 20–55秒：F01/F02/F04/F09/本局主题A，权重30/20/15/15/20。
- 55–90秒：F01/F02/F04/F09/主题A/B/C，权重18/14/12/10/16/16/14；主题种按自己的活动深度出生。
- F06仍在72秒和84秒各一次独立计划，不进入普通权重；不保证捕获。

每15秒保留一个浅层普通机会。首次遇到新类别用短名签或图鉴提示解释轮廓/占格；不在操作中弹整屏教学。主题差异为局内取舍服务，不能只换鱼的颜色。

沿用群间隔2.8±0.3/2.4±0.3/2.2±0.35秒与紧密/疏散/单或双目标模板。可捕自由实体上限32，普通最多30，稀有预留2；环境层独立。增加种类不增加同屏密度上限。达到上限跳过普通遭遇并记录，不突然挤满。

首局教程提供一次受控成功，正式局不暗改命中或凭空补鱼。正常参与者持续无收获需要修正机会与操作可读性。

### 6.4 计分

每网到船时统一结算：

`单网分 = floor(这网所有生物的基础分之和 × 本网实际个数倍率)`

| 实际捕获个数 | 0 | 1 | 2 | 3–4 | 5–6 |
|---|---:|---:|---:|---:|---:|
| 倍率 | 0 | 1.00 | 1.10 | 1.25 | 1.50 |

例如：两条小银鱼 `(10+10)×1.1=22`；三条鱼 10/15/20 分为 `floor(45×1.25)=56`；六条小银鱼为 90 分；一条金尾鱼为 80 分。没有连网倍率、效率结算再加分或深度加分。章鱼60分+四只虾各12分为162分，三只龙虾各55分为206分；均占满六格，但个数不同。

到船前显示“鱼获×n · 占格u/6”，不提前增加正式总分。图鉴发现、最佳单网、鱼获总数也在到船时更新。中途结束/恢复不能重复入账。

## 7. 重玩理由：先把一局玩出变化

### 7.1 首版三条动力

1. **个人技能**：本机最高分、最佳单网分、最佳单网个数，结束后给出一条与本局表现对应的建议。
2. **生物发现**：十格捕获图鉴，未捕获为带轮廓的空格；捕获一次亮起，展示自己的累计个数。稀有鱼不是每日强制任务。
3. **小目标**：每局从“任意一网三条”“本局捕获三种生物”“网到一条黄鳍鱼”中选择一项，按局序轮换；只做表现提示，无额外分数、不改变鱼的刷新、不阻挡继续玩。

前三局使用预先验证过的三个不同种子，其后使用新种子；教学成功场景独立，不计纪录。已验证种子仍需兼顾紧密与疏散机会，不能都是满网演示。

### 7.2 结算后的建议

| 观察结果 | 建议文案示例 |
|---|---|
| 空网多、平均深度高 | “鱼游得很快，试着往它前面一点下网。” |
| 普通收获稳定、少多鱼网 | “看到两群鱼快靠近时，可以等半拍再撒网。” |
| 捕到新鱼 | “今天第一次遇见红鲷鱼，图鉴亮了一格。” |
| 高分但未捕到金尾 | “刚才的金尾鱼游走了，下次可以给它留一张网。” |

建议由规则生成、每局最多一条；不说玩家“手残”“浪费”。同时提供直接“再出一趟”，不强迫分享。

### 7.3 后续内容路线

只有核心试玩成立后，才增加每次只改变一两个规则的潮汐变体：鱼群换向频率、出场深度构成、紧密群窗口等；再增加配套场景美术。日期种子挑战可本地生成，但不能包装成联网榜单或防作弊比赛。无计时模式单独保存纪录，不与正式 90 秒分数混算。

增加生物种类与图鉴仍不能自动保证长期留存。本稿追求首版多局可玩；长期回访需要后续内容和真实数据验证。

## 8. 信息架构与页面需求

页面：主页 → 首次教程/继续存档 → 捕鱼 → 暂停 → 捕鱼 → 最后一网 → 结算；主页可进图鉴与设置。

| 页面 | 必须展示 | 主要操作 | 异常/边界 |
|---|---|---|---|
| 主页 | 标题、海湾、开始、最高分、图鉴入口 | 开始/继续 | 有存档优先显示继续；新开局需明确覆盖当前局 |
| 教程 | 左右移动、提前撒网、三网位、收获示例 | 按提示完成/跳过 | 不计时、不记分、不更新图鉴或正式纪录 |
| 捕鱼 | 分数、剩余秒、三网位、目标简写、声音/暂停 | 三按钮 | 按钮常驻，不被飘字覆盖 |
| 暂停 | 当前分数与鱼获、声音/低特效、继续、保存并返回 | 继续/返回 | 暂停计时、鱼和网均不动 |
| 最后一网 | “收最后一网…”、正在回收的网 | 暂停 | 禁止新投，最多约 3.97 秒，不突然丢弃网获 |
| 结算 | 总分、总个数、最好一网、鱼种、新发现、目标结果 | 再来/成绩卡/回主页 | 无捕获也可继续，不强弹分享 |
| 图鉴 | 10种可捕生物的发现状态、轮廓、名称、累计个数，另列6种观赏说明 | 查看/返回 | 尚未捕获不伪造已获得 |
| 成绩卡 | 场景、分数、鱼获、最好一网、已发现鱼种 | 保存/带入笔记 | 未有能力时说明可在小红书内使用；不复制外链 |

最近 20 局只保留本地简表，首版不做复杂趋势页。结算需显示“本机纪录”，不能暗示全服排名。

### 8.1 教程四步

1. “把船开到鱼将要经过的位置。”移动达到指定范围。
2. “按住沉网，松手张网。”低速鱼群给出水层与松手位置提示。
3. “等网收回来，看看这一网。”教程场景保证第一次有效尝试有收获；允许重试。
4. “小生物占一格，大生物占两格。”演示三网位与容量后进入正式局；一次只控制一张下沉网。

教程可跳过；再次查看在设置页提供入口。正式局不显示全程轨迹预测线。

## 9. 美术、界面与声音设计

### 9.1 主方向：琉璃海湾 · 精绘2.5D观感

关键词：通透、暖金、木质、松弛、灵动、精细材质与光影层次。采用精绘贴图、分层动画与轻量动态光影形成2.5D观感。水面有碎金反光、水下有缓慢焦散与柔光束、鱼有轮廓明暗与局部高光。提高美术投入是已确认方向，最终不能以程序几何占位为完成标准。完整制作与验收以[美术与动效设计规格](05_美术与动效设计规格.md)为准。

画面层次：天空与远岸 → 水面和渔船 → 浅水鱼层 → 中深水鱼层 → 简化海底 → 独立操作区。远景低对比，游戏对象高对比；深层仍足够明亮可辨识。

| 元素 | 颜色建议 | 使用要求 |
|---|---|---|
| 天空/卡片 | `#FFF3D9` / `#FFF9ED` | 米白暖色，不把 HUD 放到复杂水纹上 |
| 浅海/深海 | `#78D5CB` / `#246C78` | 渐变有层次，深处不接近黑色 |
| 船体/绳索 | `#A86A42` / `#E8CFA2` | 木船、绳索、鱼篓形成场景语言 |
| 主按钮 | `#E97155` | 珊瑚色撒网按钮，触达面积大于两侧 |
| 正文/外轮廓 | `#183E47` | 小字与边线保持清晰对比 |
| 稀有鱼强调 | `#F3C653` | 小范围使用，兼有独特尾形，不仅靠颜色区分 |

360px 宽参考布局：左右各 12px 外边距，顶部 HUD 约 52px，底部操作与安全区约 100–120px，中间画布按 1000:1200 等比缩放。矮屏优先保证操作区与 HUD，再缩小画布；不裁掉深层鱼或船。横屏使用等比居中和留边，不拉伸或露出更多可捕鱼域。

操作按钮高至少 56 CSS px；中间撒网区域约占操作区宽度 46%，两侧各约 24%，余量为间距。小屏鱼身目标宽约 18–34px，主要轮廓不能依靠微小鳞片区分。实际字号与尺寸在真机调整。

### 9.2 动作优先级

- 渔船：左右微倾、船尾水纹；船员抛网的姿态明确，主体位置与碰撞无关的摇摆幅度克制。
- 鱼：10种可捕主体分别体现鱼鳍、虾尾、蟹腿与触腕动作；6种观赏生物采用低频环境动画，不为每个实例制作复杂骨骼。
- 渔网：网口、网格、收绳、网兜缺一不可；有效捕获轮廓与逻辑范围一致，不能用比判定大很多的装饰网欺骗玩家。
- 反馈：鱼入网时从自由游动过渡到网兜，不用“闪光后消失”代替捕鱼过程。
- 背景：水草、气泡和光斑少量循环；不能遮挡鱼、伪装成可捕对象。

新增精修要求：鱼鳍尾、虾尾、蟹腿与触腕分件或少量关键帧，船体/船员/鱼篓分层，绳索松紧与网片跟随，收网带水滴与网兜重量感。效果随实际鱼获分级；普通收获仍完整，满网有短时更饱满的反馈。视觉尾声可以在到船后延续0.3–0.5秒，但不冻结玩法或延长网位占用。静态关键画面与10–15秒目标尺寸动态切片作为批量制作前的评审产物。

### 9.3 音频

替换旧作爆炸、警报与战斗配乐。P0 音效包括抛网、入水、入网、回船、满网、新鱼发现、按钮七类；合成或使用明确授权素材。背景使用缓慢水声/木质轻音乐，循环接缝可接受前需试听验证。音乐关/音效关分别保存；启动不强制播放，音频失败时游戏继续。

## 10. 本机记录与平台能力

- 保存最高分、最好一网、鱼种累计、最近 20 局、设置、当前未结束局。
- 当前局每五秒、暂停及页面隐藏时尽力保存；恢复先暂停。异常退出可能回退到最近一次成功存档，不承诺零丢失。
- 同一正式局的结算只能入账一次；练习/教程不写正式纪录。
- 使用新产品存储命名空间，不能读取或覆盖《深海较量》的分数、存档或勋章。
- 按在线平台文档优先选择原生 Storage；版本不满足时兼容浏览器存储，失败可内存继续。
- 成绩卡用户主动点击后生成；分享、保存失败不影响分数，取消不算发布成功。
- 无联网分析 SDK。诊断指标在开发构建本地收集；正式版只有产品需要的本机摘要。

平台规则及版本条件见调研和 TDD，不在产品界面展示技术术语。

## 11. 验收目标与决策门槛

### 11.1 行为正确性

三个网位上限、单张受控网、六格空间、一生物一归属、计分一次、松手定深、最后一网、暂停接管、输入无卡住、存档隔离、无联网依赖全部必须通过。详见开发设计与验收矩阵。

### 11.2 核心体验测试

首轮邀请 8–12 名符合目标场景的玩家，至少一半没玩过旧作；每人连续三局，分离教程和正式局。小样本只找问题，不据此推断市场留存。

| 指标 | 初始通过信号 | 失败后的行动 |
|---|---|---|
| 理解 | ≥80% 在无额外口头指导下完成教程并理解提前量 | 改提示与出生布局，不先堆奖励 |
| 基本获得感 | ≥90% 的正常参与正式局至少有一次收获 | 增加可读浅层机会，检查输入与判定 |
| 收获分布 | 大多数新手空网约 20%–40%，6/6格满载网约5%–15% | 按群形、命中位置拆分调整，不引入捕获抽奖 |
| 等待 | 正常参与者连续无收获超过 10 秒的区间较少，并且看得见机会 | 检查场上可触达性与占位时长 |
| 技巧 | 观察策略有明显收益，玩家能解释至少一次成功/失手 | 调群间窗口、网位成本和目标价值 |
| 重玩意愿 | 至少 6/10 人愿意自主再玩一局，并能说出具体理由 | 若理由只有画面好看，优先改核心玩法 |
| 变化 | 三局后多数人能指出至少两种不同捕鱼判断 | 检查遭遇重复与稀有鱼追逐是否成立 |

“6/10”为十人样本的决策提示，样本人数变化时报告原始人数与比例。愿意再玩是测试现场行为，不等于次日留存。长期回访如需验证，应另组织经用户同意的回访测试。

### 11.3 首版完成定义

核心闭环和最小内容全部实现；工程检查通过；小工具同一候选包经过创服模拟器与 Android/iOS 真机流程验证；体验反馈记录并处理阻断问题。HarmonyOS/iPad 仅对实际测试设备给出结论。详细交付条件见实施文档。

## 12. 待评审项

以下不阻塞本轮文档完成，但在正式制作前应冻结：90秒是否合适、主美术方向、10种可捕与6种观赏的命名及占格、首版平台、可接受的人力/排期。按住/松手机制与容量取舍需先在可玩原型验证；核心体验方向已确认，无需重新选择。

第一项开发动作应是验证“观察后撒网比持续撒网更有意思”的可玩原型，不能以素材完整或页面漂亮代替玩法成立。
