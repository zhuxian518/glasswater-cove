# 从多网位到单网体验：琉璃海湾产品案例

> AI 协作生成的作品集整理草稿 · 2026-10-20。事实依据为仓库代码和历史文档；需求练习、绘图修改与用户观察均待本人完成，不表示本人已独立产出或验证。

## 场景与问题假设

场景是手机上一次短时出海：玩家横移渔船，控制按住下沉与松手兜鱼，在 90 秒操作时间内获得不同鱼获。需求方明确选择轻松短局，提出“允许空网，但不能总打不到；不能每网爆满无脑刷”，并要求更多生物变化与继续玩的理由。来源见[需求历史](../README-design-history.md)和[调研约束](../research/game-references.md)。这些是项目需求方反馈，不是已开展的目标用户访谈或普遍市场结论。

待验证假设：新手能理解位置与时机决定收获；单次只管理一张网可降低注意力负担；图鉴和徽章能给重复出海提供目标。这些解释尚未被真人实验或留存数据证明。

## 真实取舍及其代价

| 决策 | 依据及当前实现 | 放弃与待核验 |
| --- | --- | --- |
| 从旧三网位收敛为一次一网 | [v0.3记录](../10_v0.3实现与验证记录.md)和需求历史；新网必须等旧网回船 | 放弃并行投网节奏；是否更易理解、更少无效点击需观察，旧多网存档兼容不代表新局仍可多网 |
| 一键按住/松手，而非另加深度拨盘 | [机制设计](../06_生物多样性与撒网机制.md)；当前代码保留最浅展开保护与到底自动展开 | 早期设计的多网内容已过时；当前规则看代码与规格。轻点有保护，但不保证命中 |
| 六格容量且大生物占两格 | [当前规格](../CURRENT_PRODUCT.md)及生物配置 | 大型价值与数量倍率产生选择；“满六格”不等于“六只”，不能按外观猜得分 |
| 生物从10种扩到20种，保留三类遭遇 | [v0.4实现记录](../13_v0.4_二十种生物与徽章扩展.md) | 不把20种同时堆屏，也不保证一局集齐；新增内容并不自动证明复玩提高 |
| 52枚徽章而非完成120枚规划 | 同上及[徽章配置](../../src/config/badges.js)；收藏/手艺/组合/日常四类 | 控制首版范围；徽章无数值加成，无付费抽奖，不用强奖励掩盖核心操作问题 |

生物与徽章扩展是对“变化、继续玩的理由”的产品回应。记录可证明实施范围，不能证明用户愿意为它持续回来。

## 实现证据与流程

| 需要复核的行为 | 可检查证据 |
| --- | --- |
| 一网回船后再抛 | [FishingSimulation](../../src/core/FishingSimulation.js) 的 `command` 拒绝已有在途网；`return` 后移除 |
| 按住、松手和展开保护 | 同文件 `CAST → DESCEND → OPEN → HOLD → RETRACT`；轻点先到最小展开深度 |
| 90秒后处理最后一网 | 同文件 `PLAYING → DRAINING → ENDED`；结束操作不等于丢弃在途网 |
| 回船积分与容量 | [scoring](../../src/systems/scoring.js)、生物配置及模拟的 `usedSlots`/`return` |
| 收藏、跨局与重复结算保护 | [Progress](../../src/systems/Progress.js)、[StorageAdapter](../../src/platform/StorageAdapter.js) |
| 暂停/恢复与双构建 | [main](../../src/main.js)、[输入](../../src/input/InputAdapter.js)、[构建](../../scripts/build.mjs) |

[流程图](user-flow.svg)把界面状态与模拟状态分开。恢复先进入暂停页；暂停不生成第二张网；正常新局一次一网，旧存档迁移按历史兼容规则收完已有网。
