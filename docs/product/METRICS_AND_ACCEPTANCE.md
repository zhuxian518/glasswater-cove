## 最小观察设计

先招募3名未玩过本作、同意记录操作的参与者，每人第一次独立游玩和可选第二局。固定构建版本、设备、是否触屏、是否接受提示；允许自然退出。主持人先不教“按住/松手”，记录首次困难后再提供标准提示。三人仅用于发现问题，不能推断总体比例或显著性。

每次开始记 `session_id`、构建/版本、匿名参与编号、设备类型、开始/退出原因；用本地观察表或经同意录屏，不上传个人身份、声音或存档。本方案尚未实现自动埋点，不将其写成已有分析系统。

## 口径与目标

| 指标 | 分子 / 分母与去重 | 采集方式 | 建议门槛及解释 |
| --- | --- | --- | --- |
| 首次操作理解 | 无提示完成按住→松手→回船且能复述 / 所有开始首局的参与者 | 主持人计时、是否提示、复述原话；每人仅首局一次 | 3/3为继续迭代提示，低于则先改提示；不是总体成功率 |
| 完整局完成 | 看见结算页人数 / 开始首局人数 | 自然退出也计入分母，记录原因 | 不设商业达标值；逐人报告，避免排除失败者美化 |
| 空网率 | `emptyNets` / `completedNets` | 逐局记录源码同口径统计；分母0标不适用 | 暂不设理想百分比；结合“连续落空是否无法解释”的访谈决定 |
| 满载率 | `fullNets` / `completedNets` | 满载按六格，逐局及合并结果均保留 | 不能以越高越好；与空网率共同观察是否无脑刷 |
| 被阻止再投的尝试 | 在途网时试图再次抛网次数 / 所有有网在途的抛网尝试次数 | 观察表记录尝试，当前统计不直接提供该分母 | 重复出现且不理解原因时优先解释；不代表游戏应允许多网 |
| 当场复玩 | 主动选择再出海人数 / 已到结算且有时间自由选择人数 | 记录是否主持人建议；未结算人数另报 | 仅描述行为，不能叫次日留存 |
| 藏品理解 | 能解释徽章不改概率/积分人数 / 看过徽章说明人数 | 看说明后复述，未看者单列 | 如出现误解优先改说明；不以解锁多作为体验成功 |

比例同时报告原始人数或网数。不得把多局同一人的几十张网当作几十名独立用户；每人至少保留逐局结果。后续比较两个方案时使用同任务、可比设备与随机/平衡顺序，先补样本计划再做结论，不从三人推因果。

## 工程护栏与验收

- 正常新局最多一张在途网、容量不超过六格、同一鱼不重复捕获；旧多网档案按迁移边界单列。
- 90秒后停止新操作、完成在途网再结算；重复 runId 不重复入账。
- 暂停/取消后恢复不新建网；本地保存失败明确提示，不声称永久保存。
- 分享/相册/评论仅主动触发，不把草稿路由算发布；不得为采集引入运行时网络。

规则验收以源码及项目测试为准；2026-10-20[当前规格](../CURRENT_PRODUCT.md)记录的历史49项检查不替代本方案的用户观察，也不是AI效果评测。真实容器、Android/iOS和性能范围继续按[容器检查](../14_v0.4.1_小红书候选包检查记录.md)留待核验。
